# Высокоуровневые методы программирования и информатики

Лабораторные работы по дисциплине. Автор: Роман Хадралиев

Консольное приложение на Kotlin для проверки прав доступа пользователей к иерархическим ресурсам. В ходе развития проекта данные (пользователи, ресурсы, правила доступа) были вынесены из кода в реляционную базу данных **H2**. Пароли хранятся в виде SHA-256-хэшей с солью.

В рамках **лабораторной работы №7** проект был успешно мигрирован на **Spring Boot** (используется исключительно как IoC/DI-контейнер) и систему сборки **Maven**. Приложение работает тихо и сообщает результат через код возврата; вывод на экран возможен только при запросе справки.

---

## Требования

- **JDK 17** или выше;
- **Maven** (или использование встроенного `mvnw`/`mvnw.cmd`).

---

## Локальный запуск и тестирование

### 1. Сборка (Fat JAR)
Проект собирается с помощью Maven. Скрипт автоматически скачает все зависимости, скомпилирует исходники на Kotlin, прогонит тесты и упакует всё в единый исполняемый `jar`-файл.
```bash
./scripts/build.sh
# или напрямую через Maven Wrapper:
./mvnw clean package -DskipTests
```
*Собранный файл будет лежать по пути `target/access-control-app-1.0.0.jar`.*

### 2. Запуск приложения
```bash
java -jar target/access-control-app-1.0.0.jar --login <логин> --password <пароль> --action <действие> \
                                              --resource <путь> --volume <объём>
```

**Пример:**
```bash
java -jar target/access-control-app-1.0.0.jar --login alice --password qwerty --action read --resource A.B.C --volume 10
echo "exit code: $?"
```

Справка:
```bash
java -jar target/access-control-app-1.0.0.jar --help
```

### 3. База данных
Инициализация базы данных H2 (создание таблиц и наполнение тестовыми данными: Алиса, Боб, Кэрол) теперь происходит **автоматически при первом запуске приложения** благодаря механизму `spring.sql.init`. 
Скрипты `schema.sql` и `data.sql` лежат в папке `src/main/resources/`.

### 4. Тестирование
Все модульные тесты (JUnit 5) запускаются автоматически во время сборки. Вы можете запустить их отдельно:
```bash
./mvnw test
```

**Интеграционные тесты (черный ящик):**
```bash
./scripts/integration_test.sh
```

### 5. Логирование
В соответствии с требованиями, **логи не выводятся в консоль**. Логирование (через `Logback` и `SLF4J`) настроено в файл:
*   Путь к логам: `logs/app.log`
*   Настроена ежедневная ротация файлов и ограничение по размеру.

## Поддерживаемые аргументы

| Короткий | Длинный      | Описание                                              |
|----------|--------------|-------------------------------------------------------|
| `-l`     | `--login`    | Логин пользователя                                    |
| `-p`     | `--password` | Пароль пользователя                                   |
| `-a`     | `--action`   | Действие над ресурсом: `read`, `write`, `execute`     |
| `-r`     | `--resource` | Путь до ресурса, сегменты разделены точками           |
| `-v`     | `--volume`   | Запрашиваемый объём ресурса (целое положительное)     |
| `-h`     | `--help`     | Показать справку                                      |

## Архитектура и Spring Boot (Лаба №7)

Проект разделен по слоям чистой архитектуры (`domain`, `application`, `infrastructure`, `presentation`).
- **IoC/DI**: Создание объектов полностью управляется Spring-контейнером. Классы размечены аннотациями `@Service`, `@Repository`, `@Component`. Ручное создание зависимостей через `new` (класс `ApplicationFactory`) удалено.
- **Точка входа**: Обработка аргументов командной строки перенесена в класс `CliRunner`, реализующий интерфейс `CommandLineRunner`.
- **База данных**: Подключение к H2 настроено через `DataSource` Spring Boot (файл `application.properties`).
- **Веб-сервер**: Отключен с помощью параметра `spring.main.web-application-type=none`.

## CI/CD (GitHub Actions)

В проекте настроены пайплайны непрерывной интеграции и доставки:
*   **Основная ветка:** `master`.
*   **CI (`.github/workflows/ci.yml`):** запускается при создании и обновлении Pull Request в `master`. Выполняет сборку через Maven (`./mvnw`), модульные тесты, интеграционные тесты, анализ кода (CodeQL) и отправляет уведомление в Telegram.
*   **CD (`.github/workflows/cd.yml`):** запускается при `push` в ветку `master`. Выполняет все проверки, собирает Docker-образ, тестирует коды его завершения, публикует образ в Docker Hub, создает **GitHub Release** с прикрепленным fat-jar (`target/*.jar`) и отправляет уведомление в Telegram.
